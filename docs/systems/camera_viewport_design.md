# 系统文档：摄像机与视口系统设计（Camera & Viewport Design）

> 本文档描述改善后的摄像机与视口系统的设计思路、问题分析与解决方案。

---

## 1. 问题分析（Problem Analysis）

### 1.1 问题1：同向移动时的视觉感知问题

**现象：**
- 当两个玩家同时往一个方向移动时，视觉上很奇怪，仿佛没有在移动。

**根本原因：**
- 当前摄像机跟随**质心**（center of mass = (celu + ak) / 2）
- 当两个玩家同向同速移动时：
  - 质心也在移动（世界坐标）
  - 但两个玩家**相对于质心的位置**保持不变
  - 因此视觉上看起来像静止不动

**影响：**
- 玩家失去空间移动的感知
- 影响游戏体验的沉浸感
- 可能让玩家误以为操作无效

### 1.2 问题2：引力扩张时玩家超出画布

**现象：**
- 当能量累积到一定程度，引力扩张（maxDistance 增大）时，玩家有时候会超出画布范围，摄像机没有跟随。

**根本原因：**
1. **延迟问题**：CSS `transition-transform duration-100` 导致摄像机跟随有延迟
2. **边界缺失**：没有边界检查机制，当玩家快速移动或距离很大时，可能超出可视范围
3. **跟随策略单一**：仅跟随质心，当两个玩家距离很远时，质心可能在两者中间，但单个玩家可能已经超出屏幕

**影响：**
- 玩家可能丢失视野，看不到自己的角色
- 影响游戏可玩性
- 在高 Tier（DEEP/ASCENSION）时问题更明显（maxDistance = Infinity）

---

## 2. 设计目标（Design Goals）

### 2.1 核心目标

1. **确保两个玩家始终在视野内**
   - 无论距离多远，两个玩家都应该可见
   - 优先保证可玩性

2. **增强移动感知**
   - 即使相对位置不变，也要让玩家感知到移动
   - 通过视觉反馈强化空间感

3. **平滑跟随**
   - 摄像机跟随应该平滑但及时
   - 避免延迟导致的玩家丢失

4. **保持设计主题**
   - 维持"关系共同体"的视觉主题
   - 摄像机跟随策略应该强化协作感

### 2.2 设计约束

- **技术约束**：使用 DOM + CSS transform（非 Canvas/WebGL）
- **性能约束**：每帧更新，需要高效计算
- **兼容性**：需要支持不同屏幕尺寸

---

## 3. 解决方案设计（Solution Design）

### 3.1 方案概述

采用**多策略混合的摄像机系统**：

1. **边界框跟随（Bounding Box Following）**
   - 计算两个玩家的边界框（bounding box）
   - 摄像机跟随边界框中心，而非质心
   - 确保两个玩家都在视野内

2. **动态缩放（Dynamic Zoom）**
   - 根据两个玩家的距离动态调整缩放
   - 距离远时缩小，距离近时放大
   - 确保两个玩家始终在视野内

3. **平滑插值跟随（Smooth Interpolation）**
   - 使用平滑插值而非 CSS transition
   - 确保及时响应，同时保持平滑

4. **视觉反馈增强（Visual Feedback Enhancement）**
   - 通过背景移动、粒子效果等增强移动感知
   - 即使相对位置不变，也能感知到移动

### 3.2 详细设计

#### 3.2.1 边界框跟随策略

**计算方式：**
```
boundingBox = {
  minX: min(celu.x, ak.x),
  maxX: max(celu.x, ak.x),
  minY: min(celu.y, ak.y),
  maxY: max(celu.y, ak.y)
}

centerX = (minX + maxX) / 2
centerY = (minY + maxY) / 2
```

**优势：**
- 确保两个玩家都在视野内
- 当玩家同向移动时，边界框中心也会移动，增强移动感知
- 简单高效

**边距处理：**
- 添加边距（padding），确保玩家不会太靠近屏幕边缘
- 边距大小可根据玩家距离动态调整

#### 3.2.2 动态缩放策略

**缩放计算：**
```
distance = getDistance(celu, ak)
screenWidth = window.innerWidth
screenHeight = window.innerHeight

// 计算需要的缩放比例
requiredWidth = distance + padding * 2
requiredHeight = distance + padding * 2

scaleX = screenWidth / requiredWidth
scaleY = screenHeight / requiredHeight
scale = min(scaleX, scaleY)

// 限制缩放范围
scale = clamp(scale, minScale, maxScale)
```

**缩放范围：**
- `minScale = 0.5`：最小缩放，避免过度缩小
- `maxScale = 1.0`：最大缩放，正常大小
- 缩放中心：边界框中心

**优势：**
- 自动适应玩家距离
- 确保两个玩家始终可见
- 在高 Tier 时特别有用（距离可能很大）

#### 3.2.3 平滑插值跟随

**插值方式：**
```
targetX = -centerX * scale + screenWidth / 2
targetY = -centerY * scale + screenHeight / 2

// 每帧插值
currentX += (targetX - currentX) * lerpFactor
currentY += (targetY - currentY) * lerpFactor
```

**插值系数：**
- `lerpFactor = 0.2-0.3`：平衡响应速度和平滑度
- 值越大，响应越快，但可能不够平滑
- 值越小，越平滑，但可能有延迟

**优势：**
- 避免 CSS transition 的延迟问题
- 可精确控制跟随速度
- 性能更好（在 requestAnimationFrame 中计算）

#### 3.2.4 视觉反馈增强

**背景移动：**
- StarField 组件可以独立移动，提供移动感知
- 即使玩家相对位置不变，背景也在移动

**粒子效果：**
- 可以添加粒子轨迹，增强移动感
- 粒子位置相对于世界坐标，而非屏幕坐标

## 4. 配置参数（Configuration Parameters）

### 4.1 摄像机参数

```typescript
CAMERA_CONFIG = {
  // 边界框边距
  padding: 150,              // 像素，确保玩家不靠近边缘
  
  // 缩放范围
  minScale: 0.5,             // 最小缩放（50%）
  maxScale: 1.0,             // 最大缩放（100%）
  
  // 插值系数
  lerpFactor: 0.25,          // 0.2-0.3 之间，平衡响应和平滑
  
  // 缩放阈值
  distanceForMinScale: 800,  // 距离超过此值时使用最小缩放
  distanceForMaxScale: 200,  // 距离小于此值时使用最大缩放
}
```

### 4.2 参数调优建议

- **padding**：根据玩家实体大小和屏幕尺寸调整
- **lerpFactor**：根据游戏节奏调整，快节奏游戏可以增大
- **缩放范围**：根据游戏设计调整，如果希望玩家始终看到更多内容，可以减小 minScale

## 6. 设计权衡（Design Trade-offs）

### 6.1 质心 vs 边界框中心

**质心跟随：**
- ✅ 符合"关系共同体"主题
- ❌ 同向移动时视觉感知差
- ❌ 距离远时可能丢失玩家

**边界框中心跟随：**
- ✅ 确保两个玩家都在视野内
- ✅ 同向移动时也有移动感知
- ⚠️ 可能偏离"质心"主题（但可以通过其他方式强化主题）

**选择：边界框中心**（优先保证可玩性）

### 6.2 固定缩放 vs 动态缩放

**固定缩放：**
- ✅ 简单，性能好
- ❌ 距离远时可能丢失玩家
- ❌ 距离近时视野浪费

**动态缩放：**
- ✅ 自动适应，确保可见性
- ✅ 更好的空间利用
- ⚠️ 可能让玩家感到"被拉近/推远"

**选择：动态缩放**（优先保证可见性）

### 6.3 立即跟随 vs 平滑跟随

**立即跟随：**
- ✅ 无延迟，响应快
- ❌ 可能过于生硬

**平滑跟随：**
- ✅ 视觉更平滑
- ⚠️ 可能有延迟

**选择：平滑插值跟随**（平衡响应和平滑）

## 7. 未来扩展（Future Extensions）

### 7.1 可扩展功能

1. **摄像机震动（Camera Shake）**
   - 碰撞时添加震动效果
   - 增强反馈

2. **摄像机预测（Camera Prediction）**
   - 根据玩家速度预测位置
   - 提前移动摄像机

3. **区域锁定（Area Lock）**
   - 在某些区域锁定摄像机
   - 用于特殊关卡设计

4. **多目标跟随（Multi-target Following）**
   - 如果有多个重要目标，可以智能跟随
   - 用于未来扩展

### 7.2 性能优化

1. **视锥剔除（Frustum Culling）**
   - 只渲染视野内的元素
   - 提升性能

2. **LOD 系统（Level of Detail）**
   - 根据距离调整细节
   - 优化渲染

## 9. 总结（Summary）

改善后的摄像机系统采用**边界框跟随 + 动态缩放 + 平滑插值**的混合策略，解决了：

1. ✅ **同向移动感知问题**：通过边界框跟随增强移动感知
2. ✅ **玩家超出画布问题**：通过动态缩放和边界检查确保可见性
3. ✅ **跟随延迟问题**：通过平滑插值替代 CSS transition

同时保持了游戏的设计主题和可玩性。
